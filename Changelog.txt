l4t-r39.2.1 community port (2026-09-28)
==========================
    - Support for L4T-39.2.1 / Jetpack 7.2.1 on Jetson Orin (kernel 6.8)
        - camera-core changes from l4t-r38.4, fitted to 39.2.1
        - fr_* drivers and Orin overlays from l4t-r36.4.4
    - build-tested with OE4T meta-tegra; not yet tested on hardware
    - ISP files and build scripts unchanged from l4t-r36.4.4
    - hardware test 2026-09-28 (Orin Nano devkit Super, IMX900 over GMSL3):
        - probe and raw V4L2 capture at 60 fps work
        - Argus needs an IMX900 NITO file (Jetpack 7.2 rejects .isp)
        - V4L2 controls start at their minimum (1.5 fps) until set
      see TEST-RESULTS-l4t-r39.2.1.md
    - fr_imx900: controls start at their DT defaults (72 fps / 10 ms) instead of the minimum
    - stock Jetpack 7.2.1 (2026-09-30):
        - on-target build: NVIDIA's 39.2.1 top-level OOT Makefile,
          build/target_build.sh rewritten (build, check, install, uninstall)
        - install of the camera stack into updates/framos with a depmod
          override and a symbol CRC check; stock packages untouched
        - jetson-config-camera tools: Jetpack 7 jetson-io, separate
          FramosCamera boot entry, Orin Nano/NX header name
        - tests/hw: pytest hardware test suite with per-board profiles
          (AGX Orin FPA-4.A/AGX J5 direct; Orin Nano/NX cam1 direct and GMSL3;
          Orin Nano Jetpack 6 reference)
        - built and installed on AGX Orin; hardware test with FPA-4.A/AGX pending
        - Orin Nano (stock Jetpack 7.2.1), IMX900 direct and GMSL3: probe,
          raw V4L2 72/117/125 fps, Argus with imx900_rear_framos.nito
          (mode 0 at 72 fps; mode 5 at 58.5 fps, as on Jetpack 6)
        - compared with a stock Jetpack 6.2.1 + FRAMOS l4t-r36.4.4 reference
        - fix: depmod overrides name the module file (kmod 31)
